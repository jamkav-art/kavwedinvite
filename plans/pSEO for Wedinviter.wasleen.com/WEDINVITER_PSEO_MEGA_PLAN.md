## 📐 DATABASE SCHEMA (Modified for Wedding Industry)

### **Table 1: `wedding_locations`**

```sql
CREATE TABLE wedding_locations (
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL,              -- "Mumbai", "Delhi NCR", "Bengaluru"
  slug TEXT NOT NULL UNIQUE,        -- "mumbai", "delhi-ncr", "bengaluru"
  type TEXT NOT NULL,               -- "city", "state", "union-territory"
  state TEXT,                       -- "Maharashtra", "Karnataka"
  population INTEGER,               -- For prioritization
  search_volume INTEGER,            -- Monthly searches for "[city] wedding"
  priority INTEGER DEFAULT 50,     -- 1-100 (100 = highest priority)
  latitude DECIMAL(10, 8),
  longitude DECIMAL(11, 8),
  created_at TIMESTAMP DEFAULT NOW()
);

-- Index for fast lookups
CREATE INDEX idx_location_priority ON wedding_locations(priority DESC, search_volume DESC);
```

**Data**: 28 states + 8 UTs + 100 cities = **136 locations**


### **Database Functions**

```sql
-- Function to get next batch of items to generate (priority-based)
CREATE OR REPLACE FUNCTION get_next_wedding_queue_items(p_limit INTEGER)
RETURNS TABLE (
  queue_id INTEGER,
  location_name TEXT,
  topic_name TEXT,
  subtopic_name TEXT,
  target_keyword TEXT,
  priority_score INTEGER
) AS $$
BEGIN
  RETURN QUERY
  SELECT
    cq.id AS queue_id,
    wl.name AS location_name,
    wt.name AS topic_name,
    ws.name AS subtopic_name,
    cq.target_keyword,
    cq.priority_score
  FROM content_queue cq
  JOIN wedding_locations wl ON cq.location_id = wl.id
  JOIN wedding_topics wt ON cq.topic_id = wt.id
  LEFT JOIN wedding_subtopics ws ON cq.subtopic_id = ws.id
  WHERE cq.status = 'pending'
    AND (cq.scheduled_date IS NULL OR cq.scheduled_date <= CURRENT_DATE)
  ORDER BY cq.priority_score DESC, cq.created_at ASC
  LIMIT p_limit;
END;
$$ LANGUAGE plpgsql;
```

## 📈 SEO STRATEGY (World-Class Approach)

### **1. Keyword Research & Prioritization**

**Tools to Use**:

- Google Keyword Planner (free)
- Semrush (paid, ₹99/month trial)
- Ahrefs (paid)
- Google Trends (free)
- Answer The Public (free tier)

**Research Process**:

1. Extract search volume for each location × topic combination
2. Assess keyword difficulty (KD)
3. Calculate priority score: `(Volume / KD) × Location_Priority`
4. Sort queue by priority score
5. Generate highest-ROI pages first

**Example Priority Calculation**:

```
Keyword: "digital wedding invitations in Mumbai"
Search Volume: 1,200/month
Keyword Difficulty: 25
Location Priority: 100 (Tier 1)
Topic Priority: 100 (Primary pillar)

Priority Score = (1,200 / 25) × (100/100) × (100/100) = 48

vs.

Keyword: "wedding decorations in Bareilly"
Search Volume: 150/month
Keyword Difficulty: 15
Location Priority: 30 (Tier 3)
Topic Priority: 60 (Supporting pillar)

Priority Score = (150 / 15) × (30/100) × (60/100) = 1.8

Mumbai invitations = 26x higher priority!
```
