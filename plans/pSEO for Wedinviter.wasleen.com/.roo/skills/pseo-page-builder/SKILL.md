## Objective

The Page Builder is the rendering layer of the WedInviter pSEO system. It takes content generated by the AI pipeline (stored in `published_pages`) and converts it into fully rendered, SEO-optimized HTML pages served via Next.js App Router with Incremental Static Regeneration ISR.

This skill defines:

- **Dynamic Route Architecture**: 12 pillar route groups with `[location]/[subtopic]` params
- **Template Mapping**: How each content pillar maps to render components
- **Page Rendering Pipeline**: How `published_pages` JSON content is hydrated into React components
- **ISR Strategy**: Caching rules, revalidation windows, and stale-while-revalidate behavior
- **Sitemap Generation**: Automatic XML sitemap creation for all published pages
- **Component Library**: Reusable rendering components for each content section type

| Field                 | Source                | Type    | Description                                                                            |
| --------------------- | --------------------- | ------- | -------------------------------------------------------------------------------------- |

| `is_hub_page`         | Route type            | boolean | True for `/[pillar]/[location]` hub pages, false for `/[pillar]/[location]/[subtopic]` |

## Dynamic Route Architecture

### Route Tree

The pSEO system uses Next.js App Router with the following route structure:

```
app/
├── [pillar]/                              # Hub page: topic overview + all locations
│   ├── page.tsx                           # e.g., /wedding-invitations
│   │
│   ├── [location]/                        # City hub page: topic + location overview
│   │   ├── page.tsx                       # e.g., /wedding-invitations/mumbai
│   │   │
│   │   └── [subtopic]/                    # Full content page
│   │       └── page.tsx                   # e.g., /wedding-invitations/mumbai/digital-invitations
│   │
│   └── [location]/[subtopic]/page.tsx     # (duplicate for catch-all safety)
│
├── sitemap.ts                             # Dynamic sitemap generation
└── robots.ts                              # Robots.txt with sitemap reference
```

## Page Rendering Pipeline

The page builder follows this pipeline for every incoming request:

```
1. Receive request: GET /[pillar]/[location]/[subtopic]
       │
2. Parse URL segments (pillar_slug, location_slug, subtopic_slug)
       │
3. Fetch from published_pages WHERE url_path = /[pillar]/[location]/[subtopic]
       │
4. If page found → render full content layout
   If page not found → render 404 or fallback content
       │
5. Inject JSON-LD structured data (Article, FAQPage, BreadcrumbList, LocalBusiness)
       │
6. Apply ISR headers (Cache-Control: public, s-maxage=86400, stale-while-revalidate)
       │
7. Return rendered HTML
```

### Page Data Fetching

```typescript
// Shared data-fetching pattern for all 12 pillar routes
async function fetchPublishedPage(
  supabase: SupabaseClient,
  pillar: string,
  location: string,
  subtopic: string,
): Promise<PublishedPage | null> {
  const urlPath = `/${pillar}/${location}/${subtopic}`;

  const { data, error } = await supabase
    .from("published_pages")
    .select("*")
    .eq("url_path", urlPath)
    .single();

  if (error || !data) {
    console.error(`❌ Page not found: ${urlPath}`, error);
    return null;
  }

  return data as PublishedPage;
}

// Increment view count (fire-and-forget, non-blocking)
async function incrementViewCount(
  supabase: SupabaseClient,
  pageId: number,
): Promise<void> {
  await supabase.rpc("increment_page_view", { page_id: pageId });
}
```

### generateStaticParams

For ISR with static generation at build time:

```typescript
export async function generateStaticParams() {
  const supabase = createClient(
    process.env.SUPABASE_URL!,
    process.env.SUPABASE_SERVICE_ROLE_KEY!,
  );

  const { data } = await supabase
    .from("published_pages")
    .select("url_path")
    .like("url_path", "/wedding-invitations/%"); // Filter per pillar

  return (data || []).map((page) => {
    const parts = page.url_path.split("/");
    return {
      location: parts[2],
      subtopic: parts[3],
    };
  });
}
```

**Important**: Each of the 12 pillar routes must filter by its own pillar prefix in the `LIKE` query.

## Content Component Hierarchy

The page builder renders JSON content from `published_pages` using a set of reusable React components.

### Top-Level Page Layout

```tsx
// app/[pillar]/[location]/[subtopic]/page.tsx
export default async function PillarPage({
  params,
}: {
  params: { location: string; subtopic: string };
}) {
  const pillar = "wedding-invitations"; // Set per route file
  const { location, subtopic } = params;

  const page = await fetchPublishedPage(supabase, pillar, location, subtopic);
  if (!page) return <NotFoundPage />;

  return (
    <article className="max-w-4xl mx-auto px-4 py-8">
      {/* 1. SEO Metadata (injected via next/head) */}
      <SEOMetadata
        title={page.title}
        metaDescription={page.meta_description}
        canonicalUrl={page.canonical_url}
      />

      {/* 2. JSON-LD Schema Script */}
      <Script
        id="schema-jsonld"
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(page.schema_json) }}
      />

      {/* 3. Hero / H1 Section */}
      <HeroSection h1={page.h1_heading} location={location} pillar={pillar} />

      {/* 4. Introduction */}
      <IntroSection intro={page.intro_text} />

      {/* 5. Benefits Grid */}
      <BenefitsGrid benefits={page.benefits} />

      {/* 6. Main Content Sections */}
      {page.content_sections?.map((section, index) => (
        <ContentSection key={index} section={section} />
      ))}

      {/* 7. Local Insights */}
      <LocalInsightsPanel insights={page.local_insights} />

      {/* 8. Vendor Recommendations */}
      <VendorRecommendations vendors={page.vendor_recommendations} />

      {/* 9. FAQs */}
      <FAQSection faqs={page.faqs} />

      {/* 10. Testimonials */}
      <TestimonialCarousel testimonials={page.testimonials} />

      {/* 11. Pricing Table */}
      <PricingTable pricing={page.pricing_table} />

      {/* 12. Call-to-Action */}
      <CTASection cta={page.cta_section} />

      {/* 13. Related Topics (Internal Links) */}
      <RelatedTopics topics={page.related_pages} />
    </article>
  );
}
```

## ISR Configuration

### Per-Route Configuration

Each dynamic route file must export a `revalidate` constant:

```typescript
// app/[pillar]/[location]/[subtopic]/page.tsx
export const revalidate = 86400; // 24 hours - ISR revalidation
export const dynamic = "force-static"; // Use ISR, not SSR

// Optional: fetch data at build time
export const dynamicParams = true; // Allow generating pages on-demand
```

### ISR Strategy Matrix

| Page Type                     | `revalidate` | Rationale                                         |
| ----------------------------- | ------------ | ------------------------------------------------- |
| Subtopic pages (full content) | 86400 (24h)  | Content generated daily; daily refresh sufficient |
| Location hub pages            | 43200 (12h)  | Links to new subtopic pages added daily           |
| Pillar hub pages              | 21600 (6h)   | New locations may be added; faster refresh        |
| Sitemap                       | 3600 (1h)    | New pages published daily; hourly refresh         |

### Cache Headers

The Vercel Edge Network adds these headers automatically when using ISR:

```
Cache-Control: public, s-maxage=86400, stale-while-revalidate=259200
```

This means:

- Page is cached at the CDN edge for 24 hours (s-maxage=86400)
- After 24h, stale version is served while revalidating in background (stale-while-revalidate=259200 = 3 days)
- If revalidation fails, stale version continues to be served for up to 3 days

### On-Demand Revalidation

After each content generation run, the script calls the revalidation endpoint:

```typescript
// /app/api/revalidate/route.ts
export async function POST(request: Request) {
  const { searchParams } = new URL(request.url);
  const secret = searchParams.get("secret");

  if (secret !== process.env.VERCEL_REVALIDATE_SECRET) {
    return Response.json({ error: "Invalid secret" }, { status: 401 });
  }

  const pillar = searchParams.get("pillar");
  const slug = searchParams.get("slug");

  if (pillar && slug) {
    await revalidatePath(`/${pillar}/${slug}`);
  } else {
    // Revalidate all published pages
    await revalidatePath("/[pillar]/[location]/[subtopic]", "page");
  }

  return Response.json({ revalidated: true });
}
```

## Hub Pages

### Pillar Hub Pages (`/[pillar]`)

A hub page for each of the 12 pillars that lists all available locations and subtopics.

```
/wedding-invitations              → Lists all locations with links
/wedding-venues                   → Lists all locations with links
... (12 pillars total)
```

**Content**: Dynamically generated from `published_pages` grouped by location:

```typescript
// Fetch all unique locations for this pillar
const { data: locations } = await supabase
  .from("published_pages")
  .select("url_path")
  .like("url_path", "/wedding-invitations/%")
  .order("url_path");

// Group by location
const grouped = locations.reduce(
  (acc, page) => {
    const location = page.url_path.split("/")[2];
    acc[location] = acc[location] || [];
    acc[location].push(page.url_path);
    return acc;
  },
  {} as Record<string, string[]>,
);
```

### Location Hub Pages (`/[pillar]/[location]`)

A city-level hub page for each pillar + location combination:

```
/wedding-invitations/mumbai       → Lists all subtopics in Mumbai
/wedding-venues/mumbai            → Lists all venue types in Mumbai
```

**Content**: Lists all subtopics for this pillar + location from `published_pages`. Shows:

- Page title and brief excerpt
- Link to each subtopic page
- Count of pages published for this location

## Sitemap Generation

### Dynamic Sitemap

```typescript
// app/sitemap.ts
import { createClient } from "@supabase/supabase-js";

export default async function sitemap() {
  const supabase = createClient(
    process.env.SUPABASE_URL!,
    process.env.SUPABASE_SERVICE_ROLE_KEY!,
  );

  const { data: pages } = await supabase
    .from("published_pages")
    .select("url_path, published_at, quality_score")
    .order("published_at", { ascending: false });

  const baseUrl =
    process.env.NEXT_PUBLIC_SITE_URL || "https://wedinviter.wasleen.com";

  // Static pages
  const staticPages = [
    {
      url: baseUrl,
      lastModified: new Date(),
      changeFrequency: "weekly",
      priority: 1.0,
    },
    {
      url: `${baseUrl}/templates`,
      lastModified: new Date(),
      changeFrequency: "weekly",
      priority: 0.9,
    },
    {
      url: `${baseUrl}/contact`,
      lastModified: new Date(),
      changeFrequency: "monthly",
      priority: 0.5,
    },
  ];

  // Dynamic pSEO pages
  const pseoPages = (pages || []).map((page) => ({
    url: `${baseUrl}${page.url_path}`,
    lastModified: new Date(page.published_at),
    changeFrequency: "weekly" as const,
    priority:
      page.quality_score >= 90 ? 0.9 : page.quality_score >= 80 ? 0.8 : 0.6,
  }));

  return [...staticPages, ...pseoPages];
}
```

### Sitemap Split Strategy

When the number of published pages exceeds 50,000 (Google's sitemap URL limit), split into multiple sitemaps:

```typescript
// app/sitemap.ts — split by pillar
export default async function sitemap() {
  const pillars = [
    'wedding-invitations', 'wedding-venues', 'wedding-planning',
    'bridal-fashion', 'wedding-makeup', 'wedding-photography',
    'wedding-catering', 'wedding-decorations', 'wedding-entertainment',
    'wedding-rituals', 'wedding-gifts', 'honeymoon-planning',
  ];

  return [
    { url: `${baseUrl}/sitemap-main.xml`, lastModified: new Date(), ... },
    ...pillars.map(pillar => ({
      url: `${baseUrl}/sitemap-${pillar}.xml`,
      lastModified: new Date(),
      changeFrequency: 'daily' as const,
      priority: pillar === 'wedding-invitations' ? 1.0 : 0.7,
    })),
  ];
}
```
